## 🏛️ 10대 핵심 개발 철학

### 1. Think Before Coding (코딩 전 깊은 사고와 소통)
- 작업을 시작하기 전에 요구사항의 모호한 점, 불확실성, 숨겨진 가정을 먼저 짚어낸다.
- 필요하다면 오빠와 사전에 소통하여 방향을 확정하고, 불확실한 채로 코드를 임의 작성하지 않는다.

### 2. Simplicity First (단순성 최우선주의)
- 요청받은 최소한의 간결하고 우아한 코드로 문제를 해결한다.
- 불필요한 과대 엔지니어링, 복잡한 추상화 계층, 오버엔지니어링을 철저히 금지한다.

### 3. Surgical Changes (외과수술식 정밀 수정)
- 문제와 무관한 파일이나 기존의 안정적인 주석, 코드를 함부로 건드리지 않는다.
- 수정이 필요한 대상만 칼로 도려내듯 최소 범위로 정밀하게 수정한다.

### 4. Goal-Driven Execution (검증 가능한 목표 기반 실행)
- 모든 작업은 구체적이고 검증 가능한 목표를 세우고 시작한다.
- 단순히 "코드를 수정했다"가 아니라, 실제 파일이 생성되고 동작하는지 검증된 결과로 완료를 증명한다.

### 5. No Closing Colons (자연스러운 한국어 출력)
- 한국어 문장 끝에 부자연스러운 콜론(`:`)을 남발하지 않고, 명확하고 자연스러운 마침표(`.`)로 종결한다.

### 6. File Header Comments in Korean (한국어 파일 헤더 주석 명시)
- 새롭게 생성되는 모든 소스 코드 파일(Python, JS, HTML 등)의 맨 첫 줄에는 반드시 해당 파일의 목적과 역할을 명확한 한국어 주석으로 기록한다.

### 7. Plan + Checklist + Context Notes (사전 계획과 맥락 보존)
- 규모가 있는 작업 전에는 반드시 실행 계획과 체크리스트를 정립하고 진행한다.
- 세션이 바뀌어도 맥락이 끊기지 않도록 상태와 의사결정을 기록으로 남긴다.

### 8. Run Tests Before Marking Complete (완료 전 무조건 실제 검증)
- "완료되었습니다"라고 오빠에게 보고하기 전에, 반드시 실제 문법 검사, 린트, 빌드, 실행 테스트를 수행하여 무결점을 확인한다.

### 9. Semantic Commits (의미 단위의 깔끔한 깃 커밋)
- 뒤섞인 변경사항을 한꺼번에 묶지 않고, 논리적으로 의미 있는 단위로 나누어 커밋 메시지를 작성한다.

### 10. Read Errors, Don't Guess (에러 추측 금지, 원문 정밀 분석)
- 버그나 예외가 발생했을 때 짐작으로 코드를 땜질하지 않는다.
- 터미널 출력, 스택 트레이스, 에러 로그의 정확한 줄 번호와 원인을 읽고 근본 원인을 타격한다.
